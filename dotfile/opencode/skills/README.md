# Skills

OpenCode/Claude skills. Each directory holds one `SKILL.md`; the tool selects a skill by matching the request against its `description`, so descriptions carry the distinct trigger phrases (English and Spanish) — trimmed to what actually triggers, because every description is permanently in context.

**This folder is published publicly.** No client name, real hostname, credential, token, national ID, employee name or engagement path may appear in any file. Run `./check-leaks.sh` before pushing — exit 1 means do not push. It derives the forbidden-word list from the engagement directories on the machine, so it stays current without maintenance.

## Layout

```
skills/
  pentest/        engagement lifecycle + vulnerability classes + hunt loop
  bugbounty/      program selection, earnings, English reporting
  report/         evidence capture, report packaging, memory/feedback
  tooling/        Burp, HTTP rotation, C2, terminal, browser evidence
  style/          code style, skill authoring, slides, image prompts, session mgmt
  README.md · check-leaks.sh · sync-claude-skills.sh
```

**OpenCode** discovers with the glob `skills/**/SKILL.md` — the nesting is transparent; a skill is addressed by its frontmatter `name`, not its path. **Claude Code** scans only ONE level (`~/.claude/skills/<name>/SKILL.md`, command name = directory basename), so it cannot see subdirs directly. To bridge that, `~/.claude/skills` is a real directory of flat symlinks — one per skill, pointing at its nested dir — regenerated by `./sync-claude-skills.sh` (run it after adding/moving/removing a skill; `--check` reports drift). `~/.config/opencode/skills` stays a symlink to this real tree. The farm is never placed inside the real tree, so OpenCode never double-registers.

Every `SKILL.md` frontmatter carries a `source:` field recording origin:

| `source` | Meaning |
| --- | --- |
| `mine` | Written by Tinmarino; encodes house style or personal tooling. |
| `public-methodology` | Authored by Tinmarino + Claude, synthesized from public sources (PortSwigger, OWASP, HackTricks, swisskyrepo). Not downloaded from any URL. |
| `own-tooling` | Tinmarino's own field tooling and engagement conventions (session.yaml keepalive, repo skeleton, `Lot/`/`Findings/`/`Report/` layouts, own C2, IP-rotation requester, the engagement dispatcher). |

## Entry point

`skill-router` is the single dispatcher for the whole suite — load it when the next step is unclear or a request is ambiguous. Inside a pentest engagement it hands off to `pentest-router`, the lifecycle dispatcher (scope gate -> recon -> registry -> lot -> exploitation -> evidence -> report -> memory).

## Conventions the pentest suite shares

- Engagement root holds `AGENTS.md`, `todo.md`, `done.md`, `MEMORY.md`, `program*.md`, `scope.md`, and `Report/`, `Findings/`, `Script/`, `Lot/`, `doc/`.
- Agents own the `AI###` finding namespace; the human's own prefix is never assigned by an agent.
- Read-only by default — state-changing methods need explicit human authorisation for a concrete payload.
- **Every HTTP request carries `X-Bug-Bounty-CyScope: Tinmarino`**, byte-exact. Verified with grep, never assumed. See `pentest-scope-gate`.
- Evidence is copied into `Report/<ID>/Ad/`, never moved out of `Findings/`.
- Markdown is never hard-wrapped; one line per paragraph, bullet or table cell.
- Nothing lives in `/tmp`. What is not on local disk is not evidence later.
